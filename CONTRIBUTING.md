# Contributing and project feedback

Thanks for taking an interest in GitRatio's public work. This repository powers the public GitHub profile. Product issues and code contributions should go to the relevant project repository.

## Where to contribute

- [anime-api](https://github.com/GitRatio/anime-api): review the documentation and existing issues before proposing API improvements.
- [anitopy](https://github.com/GitRatio/anitopy): report reproducible parsing issues or suggest targeted fixes. This repository is a fork; review the upstream project's contribution expectations before submitting changes.
- [RamRatio Desktop Helper](https://github.com/GitRatio/RamRatio-Desktop-Helper): report native-messaging compatibility issues or propose documentation improvements.
- [GitRatio profile](https://github.com/GitRatio/GitRatio/issues): report broken links, accessibility problems, or outdated descriptions in this profile.

Not all source is public. Please don't open requests for private project source code or assume a download repository accepts development PRs.

## Reporting issues

Before opening a new issue, search for duplicates. Explain what you expected, what happened, how to reproduce it, and which version and platform you used. Remove credentials, personal data, and private logs.

## Pull requests

1. Discuss larger changes in an issue first.
2. Keep the patch focused; avoid unrelated formatting and dependency churn.
3. Describe the motivation, behavior change, tests, and any compatibility or security considerations.
4. Run the checks documented by the destination repository and report the results accurately.
5. Use clear commit messages and credit actual collaborators. Never claim co-authorship without their participation.

Maintainers may ask for revisions or decline suggestions that fall outside project scope. Stars, reviews, and reactions are always voluntary—please don't trade or manufacture engagement.

## Security

Do not post exploits, access tokens, user information, or unredacted sensitive logs in public issues. If a repository publishes a security policy, use its private reporting channel instead.
